------------------------------------------------------------------------
PARTE 3. COMPROBAR ERRORES EN XML
------------------------------------------------------------------------
1. ¿Qué ocurre al eliminar temporalmente una etiqueta de cierre en libros.xml?
   Al eliminar una etiqueta de cierre (por ejemplo, </titulo> o </libro>) y ejecutar el programa de lectura, el analizador DOM falla al ejecutar builder.parse() y lanza una excepción de tipo org.xml.sax.SAXParseException.
   El mensaje de error indica que las estructuras del documento XML deben empezar y terminar dentro de la misma entidad ("The element type 'titulo' must be terminated by the matching end-tag '</titulo>'"), ya que el documento XML deja de estar "bien formado".
   Al restaurar la etiqueta de cierre en libros.xml, el documento vuelve a cumplir las reglas de sintaxis XML y el programa muestra los tres libros correctamente.


------------------------------------------------------------------------
PREGUNTA FINAL (PARTE OBLIGATORIA - LECTURA CON DOM)
------------------------------------------------------------------------
Enunciado:
"Imagina que el fichero XML está correctamente formado, pero uno de los libros no contiene la etiqueta <autor>. ¿Crees que DOM podrá leer el documento? ¿Qué ocurrirá cuando nuestro programa intente obtener el autor de ese libro? Razona tu respuesta."

Respuesta razonada:
1. ¿Podrá DOM leer el documento?
   Sí, DOM podrá abrir y analizar (parsear) el documento XML sin ningún error. Un analizador DOM estándar (sin validación DTD o XSD activa) únicamente comprueba que el documento esté "bien formado" (que exista un único nodo raíz, que todas las etiquetas abiertas se cierren adecuadamente, que no se crucen y que los atributos tengan comillas). Que a un elemento <libro> le falte la etiqueta hija <autor> no rompe las reglas de sintaxis del XML.

2. ¿Qué ocurrirá cuando nuestro programa intente obtener el autor de ese libro?
   Cuando el programa llegue a ese libro y ejecute la línea:
   String autor = libro.getElementsByTagName("autor").item(0).getTextContent();

   - libro.getElementsByTagName("autor") buscará etiquetas <autor> dentro de ese <libro> y devolverá un objeto NodeList vacío (con longitud 0).
   - Al llamar a .item(0) sobre una lista vacía, el método devolverá null.
   - Al intentar ejecutar .getTextContent() sobre null, Java lanzará una excepción en tiempo de ejecución: java.lang.NullPointerException, interrumpiendo la lectura normal y saltando al bloque catch.
   - Para evitar este fallo, habría que comprobar antes si el nodo existe (por ejemplo: Node nodoAutor = libro.getElementsByTagName("autor").item(0); y verificar que nodoAutor != null antes de pedir su getTextContent()).


------------------------------------------------------------------------
PREGUNTA FINAL (AMPLIACIÓN OPCIONAL - ESCRITURA CON DOM)
------------------------------------------------------------------------
Enunciado:
"Imagina que ejecutas dos veces seguidas tu programa de escritura, sin modificar el código. ¿Qué ocurre con el fichero nuevos_libros.xml que se generó en la primera ejecución? ¿Se conservan los libros anteriores, se duplican o se sustituye el contenido? Explica tu respuesta teniendo en cuenta cómo has programado la escritura."

Respuesta razonada:
1. ¿Qué ocurre con el fichero nuevos_libros.xml?
   Se SUSTITUYE (sobrescribe) por completo el contenido del fichero generado en la primera ejecución. No se conservan los libros anteriores ni se duplican.

2. Explicación teniendo en cuenta cómo se ha programado la escritura:
   - En primer lugar, nuestro programa crea en cada ejecución un documento DOM completamente nuevo y vacío en memoria mediante DocumentBuilder.newDocument(), sin leer ni cargar el fichero nuevos_libros.xml que ya existía en el disco.
   - En segundo lugar, al volcar el árbol DOM a disco mediante Transformer.transform(source, new StreamResult(new File("nuevos_libros.xml"))), la clase StreamResult abre un flujo de salida hacia el fichero que sobrescribe el archivo desde el principio, reemplazando todo su contenido anterior por el nuevo documento generado.
   - Si quisiéramos conservar los libros anteriores y añadir nuevos, tendríamos que cargar primero el fichero existente con builder.parse(new File("nuevos_libros.xml")), recuperar el elemento raíz <libros> con doc.getDocumentElement(), añadirle los nuevos nodos <libro> con appendChild() y finalmente guardarlo con Transformer.
